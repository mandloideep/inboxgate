# Known accepted risks

This register records unresolved security and reliability risks that the repository owner has explicitly accepted so work can continue.
An accepted risk is not a fixed risk and must not be described as a security control.

The current acceptance applies only to the exact dependency version and adapter selected by [ADR 0004](adr/0004-turso-serverless-adapter.md), as extended for credential-free loopback migrations by [ADR 0005](adr/0005-append-only-migration-protocol.md), minimum account-cursor persistence by [ADR 0006](adr/0006-minimum-account-cursor-persistence.md), ciphertext-only provider-credential persistence by [ADR 0007](adr/0007-versioned-provider-credential-encryption.md), synthetic OAuth enrollment reconciliation by [ADR 0008](adr/0008-google-oauth2-client.md), account lifecycle persistence by [ADR 0009](adr/0009-account-lifecycle-and-revocation.md), atomic current-discovery staging by [ADR 0010](adr/0010-atomic-current-discovery-staging.md), inert bounded Gmail orchestration by [ADR 0011](adr/0011-bounded-gmail-current-discovery.md), deterministic persisted gating by [ADR 0012](adr/0012-deterministic-persisted-gate.md), bounded candidate-content persistence by [ADR 0013](adr/0013-bounded-candidate-content.md), bounded account-status reads by [ADR 0015](adr/0015-bound-mcp-account-status-disclosure.md), bounded maintained-fork stream close by [ADR 0016](adr/0016-own-bounded-turso-stream-close-lifecycle.md), and bounded candidate inspection by [ADR 0017](adr/0017-bound-mcp-candidate-gate-inspection.md).
It does not authorize production credentials, runtime activation, remote migrations, live account data, plaintext provider data, live email metadata, or live Turso Cloud access.

ADR 0011 reaches credential, lifecycle, cursor, reconciliation, canonical-message lookup, and atomic current-discovery operations from a broader internal Gmail use case without adding SQL.
The use case reconciles before provider work, maps storage failures to fixed outer categories, makes one aggregate commit without same-invocation replay, preserves every existing row and value bound, and stays limited to fake or credential-free literal-loopback storage.
Those controls contain the new call path but do not close `TURSO-001` through `TURSO-005` or supply Turso Database engine evidence.

ADR 0012 reaches canonical-message and gate-decision operations from an inert deterministic evaluator.
It uses fixed parameterized SQL, one mutation attempt, separate physical proof, strict decoding, no replay, and session discard while remaining limited to fake or credential-free literal-loopback storage.
Those controls contain the new call path but do not close `TURSO-001` through `TURSO-005` or supply Turso Database engine evidence.

ADR 0013 reaches lifecycle, canonical-message, gate-decision, and candidate-content operations from an inert Gmail body-content extractor.
It uses fixed parameterized SQL, strict decoding, one mutation attempt, separate physical proof, no replay, and session discard while remaining limited to fake or credential-free literal-loopback storage.
Candidate-content rows broaden the private values and response sizes exposed to every risk in this register, and no current test supplies remote Turso Database engine evidence or pre-allocation containment.
Those controls contain the new call path but do not close `TURSO-001` through `TURSO-005`.

ADR 0016 partially contains `TURSO-003` for stream close only through one caller-owned context, exact error propagation, a fixed two-worker join, a configured fallback for `driver.Conn.Close`, terminal idempotence, and adapter redaction.
Explicit transaction commit and rollback remain background-context operations with uncertain terminal state, so `TURSO-003` remains open.
The fork does not change or close `TURSO-001`, `TURSO-002`, `TURSO-004`, or `TURSO-005`.

ADR 0015 makes bounded account listing runtime-reachable only when both MCP and operator tools are enabled and only through credential-free literal-loopback storage.
It performs one fixed typed read, rejects more than 100 or malformed rows after driver buffering, maps every failure to a fixed outer category, and exposes neither raw SQL nor a storage handle to MCP.
These controls contain the query path but do not close `TURSO-001` through `TURSO-005` or supply Turso Database engine evidence.

## Review procedure

Every direct driver upgrade must compare the exact source behavior against all open risk IDs.
The review must update the affected version, evidence, containment, and closure state before merge.

Any issue that makes the adapter runtime-reachable must list every open risk ID in its security impact and explain why the proposed use stays within the owner's acceptance.
If a feature needs behavior outside the current containment, stop and obtain a new explicit decision rather than treating this register as blanket approval.

Close a risk only after a focused issue supplies reproducible evidence for its closure criteria and updates the ADR, threat model, tests, and this register.
## Read-only candidate-inspection note

The `mail_list_review_candidates` and `mail_get_gate_reason` tools are available only to one owner-approved bearer principal under the dual MCP and review-read capability gate.
Their account filters narrow results but do not authorize access.
All email-derived preview data is `untrusted_email` and cannot authorize another action.
Candidate excerpts are explicitly excluded from both tools.
The fixed source queries bound accepted rows and output after driver buffering, so this path broadens the operations covered by `TURSO-005` without closing it.
